## Mechanism

**Chosen mechanism: `ss -tlnp` process-name filtering.**

Chromium is launched via Playwright Node with `--remote-debugging-port=0` (OS-assigned
free port). The actual port is discovered by:

1. Running `ss -tlnp` to list all listening TCP sockets with process info.
2. Filtering for lines matching the process name `chrome-headless` or `chromium`.
3. Extracting the port from the `127.0.0.1:<port>` address.
4. Polling with 500ms backoff until the port shows up (up to 15 seconds).

The discovered endpoint is `http://127.0.0.1:<port>`.

**Note:** Playwright Node 1.61 does **not** expose `browser.process()` — the
`Browser` object has no `process()` method. The `_options` property stores
launch args but not the browser PID. Hence port discovery must go through an
external mechanism (`ss`, `lsof`, `/proc`, etc.) or use a fixed env-var-resolved
port.

## Commands

```
# Launch chromium with dynamic port:
chromium.launch({ args: ["--remote-debugging-port=0", ...] })

# Discover port (no PID available from Playwright):
ss -tlnp | grep chrome-headless    # extract port from 127.0.0.1:<port>

# Python attach:
playwright.chromium.connect_over_cdp(endpoint_url)

# Snapshot:
page.ariaSnapshot()
```

## Notes

- Port `0` works — the OS assigns a free port, and `ss -tlnp` with process-name
  filtering finds it reliably on Linux.
- Fixed port fallback (env-var-resolved, e.g. `CDP_PORT=9222`) is available when
  `ss` is unavailable (macOS, Windows, containers without `ss`).
- Two CDP clients on one Chromium is a **standard, well-tested feature** of Chromium's
  DevTools Protocol — no interleaving issues observed.
- Python Playwright's `connect_over_cdp` successfully shares the browser context
  and page that Node Playwright created, without needing BrowserGym.
- The Python adapter can find the active page by iterating `browser.contexts` →
  `context.pages`, picking the one whose URL matches the MiniWoB task page.
- **Playwright 1.61 limitation:** `browser.process()` is not exposed. The
  planned `getCdpEndpoint()` method on the chromium plugin should use the
  `ss`/port-scan approach or accept a `CDP_PORT` env var.

## Recommendation

For the `getCdpEndpoint()` method on the chromium plugin: use
`--remote-debugging-port=0` and discover the port via `ss -tlnp` (Linux) with
a fallback to a `CDP_PORT` env var for non-Linux platforms. Cache the result
so the scan happens only once at lazy-init time.
